# Definition of Done для MVP фабрики

Фаза 1. Критерии «готовности» к переходу от MVP к следующему этапу (продуктивизация, дополнительные архетипы).

## MVP считается достигнутым, когда выполнено всё ниже

### Конвейер
- [ ] Реализован один полный factory run: запрос → спецификация (PRD/план/задачи) → создание репо из архетипа → CI (lint, unit, integration) → деплой в staging.
- [ ] «Запрос → staging» воспроизводимо выполняется не менее 3 раз подряд на одном и том же commit SHA (или эквивалентном входе).
- [ ] Pipeline (CI) стабильно зелёный для созданного архетипа при каждом прогоне.

### Контроль и безопасность
- [ ] Все side-effects выполняются только через tool executor (sandbox); агент не вызывает напрямую деплой, изменение ACL, доступ к секретам.
- [ ] Есть политика (allowlist + бюджеты) и проверка перед выполнением tool call; high-risk действия требуют ручного approval.
- [ ] Каждый tool call записывается в audit log; один factory run трассируется end-to-end (OTel или аналог).

### Артефакты и качество
- [ ] Используется один архетип «API service» (или эквивалент), зафиксированы контракты (JSON schema) для инструментов и выходов агента.
- [ ] В репо продукта есть базовая структура: код, тесты, конфиг CI, документация (README, при необходимости ADR).

### Документация и процесс
- [ ] Зафиксированы запрещённые действия агента ([prohibited-agent-actions.md](prohibited-agent-actions.md)).
- [ ] Заполнены risk register и data map в объёме, необходимом для MVP ([risk-register.md](risk-register.md), [data-map.md](data-map.md)).
- [ ] Есть runbook: как запустить factory run, как откатить деплой, куда смотреть логи/трейсы.

## Что не входит в DoD MVP

- Полноценный supply chain (SBOM, подпись, SLSA) в CI — фаза 6.
- Offline eval gates (RAGAs, agent missions) — фаза 5.
- Деплой в prod без явного решения оператора.
- Второй и третий архетипы (web, data pipeline) — фаза 7.
- Multi-tenancy и self-serve портал — фаза 7.
