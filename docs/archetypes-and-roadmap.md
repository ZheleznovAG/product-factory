# Архетипы: кто создаёт и как будет в будущем

Кратко: откуда берутся архетипы сейчас и как может эволюционировать фабрика.

---

## Сейчас: архетипы создаём мы

- **Архетипы** — это шаблоны продуктов в репозитории фабрики: каталог `archetypes/` (например `catalog-service`, `web-app`). Каждый архетип — готовый проект: код, тесты, Dockerfile, CI-конфиг.
- **Кто создаёт:** архетипы пишут и поддерживают вручную (разработчик/оператор фабрики). Добавить новый тип продукта = добавить новый архетип в репо и при необходимости донастроить выбор в workflow (например по `target_stack`).
- **Что делает фабрика:** по запросу выбирает один из архетипов (по `target_stack` или ключевым словам в `goal`) и вызывает tool `create_repo_from_archetype` — копирует выбранный архетип в `workspace/pf-<runId>/`. Итоговый артефакт — **копия архетипа**, без изменений кода от LLM в репо.
- **Планировщик и кодоген (LLM):** генерируют план и предложения по коду (patch sets). Эти предложения **пишутся только в audit log** (события `pipeline_plan`, `adr_draft`, `test_plan`, `codegen_patch_set`). В репо они **не применяются** — нет tool «применить patch». То есть сегодня LLM влияет на наблюдаемость и логи, но не на содержимое созданного репо.

**Итог:** да, архетипы создаём мы; фабрика создаёт «варианты архетипов», а не новые продукты «с нуля» из одного только intent. См. [strategic-fork-factory-2.md](strategic-fork-factory-2.md) (Factory 1.0 = deterministic template engine).

---

## В будущем: возможные направления

1. **Больше архетипов, тот же механизм**  
   Продолжаем вручную добавлять архетипы (data-pipeline, backend-for-frontend и т.д.). Фабрика только выбирает и копирует. Минимум изменений, предсказуемость.

2. **Применение предложений кодогена (apply patch)**  
   Добавить tool «применить patch»: после `create_repo_from_archetype` выполнять применение части предложений из `codegen_patch_set` к скопированному репо (по политике и approval). Тогда архетип остаётся базой, а LLM добавляет/меняет файлы — кастомизация под goal без ручного копипаста.

3. **Генерация продукта «из intent» (дальше)**  
   Планировщик и кодоген генерируют план и код; фабрика создаёт репо не копированием архетипа, а применением сгенерированных изменений (или генерацией с нуля в sandbox). Это уже «новые продукты из intent», а не варианты готовых шаблонов. Требует усиления RAG, политик и, возможно, durable engine (Temporal) и полноценного AI-risk контура.
