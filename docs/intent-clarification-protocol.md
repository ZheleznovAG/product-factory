# Intent Clarification Protocol

Цель: до первого результата (первого draft/plan) задать пользователю не более 3-5 коротких вопросов, чтобы уточнить intent и снизить риск неверного направления.

Протокол согласован с полями контракта [intent.schema.json](../contracts/schemas/intent.schema.json) (`outcome`, `experience`, `constraints`).

В текущем фокусе — текстовый и аудио-канал уточнения (см. ниже); остальные модальности не входят в текущий план.

## Правило 3-5 вопросов

1. Максимум 5 вопросов до первого результата.
2. Минимум 3 вопроса, если цель и ограничения сформулированы слишком общо.
3. Если после 3 вопросов `outcome` и `constraints.mustHave` уже однозначны, можно завершить уточнение раньше.
4. Каждый вопрос задаётся в формате A/B (быстрый выбор без длинного диалога), но ответ пользователя может быть:
   - `A/B` (или `1/2`);
   - короткая фраза (1-2 предложения), которая маппится в поля intent.
5. Выбор и порядок вопросов зависят от `goal` и `constraints` (urgency/quality/strictness сигналы влияют на приоритет).

## Набор вопросов A/B (примеры)

1. Outcome-фокус  
A: "Сначала быстрый MVP"  
B: "Сразу production baseline"

2. Experience-режим  
A: "Быстрее, меньше проверок"  
B: "Медленнее, но с валидациями и объяснимостью"

3. Constraint-строгость  
A: "Часть вторичных ограничений можно ослабить"  
B: "Все ограничения считаем строгими must-have"

4. Tempo (опционально, если есть неопределённость)  
A: "Короткие быстрые итерации"  
B: "Размеренный темп ради стабильности"

5. Success trade-off (опционально)  
A: "Приоритет time-to-value"  
B: "Приоритет минимизации рисков"

## Адаптивный порядок вопросов

- Базовые оси: `Outcome`, `Validation`, `Strictness`.
- Дополнительные оси: `Tempo`, `Risk` (подключаются при неопределённости или по сигналам из `goal/constraints`).
- Для целей с сигналом `production/security/compliance/stable` порядок смещается к `Strictness -> Validation -> ...`.
- Для целей с сигналом `MVP/urgent/fast` порядок смещается к `Outcome -> Tempo -> ...`.

## Mapping в intent

- `outcome.goal`: исходный goal (нормализованный).
- `outcome.result`: выбор из Outcome-фокуса + Success trade-off.
- `experience.interactionStyle`: `"Adaptive 3-5 clarification protocol (A/B + short phrase)"`.
- `experience.tempo`: вывод из Tempo-вопроса (`fast|balanced|slow`).
- `constraints.mustHave`: исходные constraints + выборы со строгим режимом.
- `confidence`: повышается по мере заполнения осей вопросов.

### Правила маппинга короткой фразы

- Сначала парсится явный выбор `A/B` (`a`, `b`, `1`, `2`, `a)`, `b)`).
- Если явного выбора нет, применяется rule-based маппинг по ключевым словам для текущей оси вопроса:
  - `Outcome`: быстрый MVP vs production baseline;
  - `Validation`: быстрый режим с меньшим числом проверок vs строгие проверки/валидации;
  - `Strictness`: ослабление вторичных ограничений vs строгие must-have;
  - `Tempo`: быстрые итерации vs размеренный темп;
  - `Risk`: time-to-value vs минимизация рисков.
- Если фраза неоднозначна:
  - задаётся один уточняющий вопрос;
  - если ответ всё ещё неоднозначен, задаётся fallback-вопрос с требованием явного выбора `A/B`.

## Раннее завершение и черновик intent

- После каждого ответа пересчитывается `currentIntentDraft` (`updateIntentDraft(goal, constraints, previousAnswers)`).
- `nextQuestion(goal, constraints, previousAnswers, currentIntentDraft)` возвращает:
  - следующий A/B вопрос, если полнота ещё недостаточна;
  - `null`, если достигнут лимит вопросов или полнота уже достаточна (`confidence` + заполненные обязательные поля).
- Минимальный порог раннего завершения: не раньше 3 ответов.

## Реализация (stub)

- Генерация вопроса детерминированная (`template-based`) через адаптивный план и `nextQuestion(...)`.
- Для LLM-режима используется `LlmIntentClarification` (через `NeuralServiceClient`) с fallback на stub.

## Аудио-слой (ASR/TTS)

- Базовый протокол уточнения работает в текстовом слое и не меняет контракт intent.
- Для голосового сценария используется внешний аудио-адаптер:
  - `ASR`: речь пользователя `->` текст (goal, constraints, ответы);
  - `Intent Clarification`: тот же протокол 3-5 вопросов по тексту;
  - `TTS`: озвучивание уточняющих вопросов и финального черновика intent.
- Ошибки распознавания и голосовые UX-механики (повтор вопроса, таймаут, barge-in) принадлежат аудио-слою, а не ядру intent.

### Канонический audio-loop для уточнения intent

1. `ASR` транскрибирует реплику пользователя в текст и возвращает confidence.
2. Если confidence ниже порога, аудио-слой делает переспрос через `TTS` и не обновляет intent.
3. Подтверждённый текст передаётся в `nextQuestion(...)`/`updateIntentDraft(...)`.
4. Следующий вопрос (или финальный черновик intent) озвучивается через `TTS`.
5. При `barge-in` озвучка прерывается, но в ядро передаётся только подтверждённый текст.

Эта схема фиксирует границу: `ASR/TTS` живут в адаптере ввода/вывода, а логика 3-5 вопросов остаётся общей для текста и аудио.

### Диалоговый цикл аудио-адаптера

1. Пользователь говорит цель или ответ.
2. `ASR` формирует текст и confidence распознавания.
3. При низком confidence аудио-слой запрашивает повтор (без изменения intent).
4. При достаточном confidence текст передаётся в `Intent Clarification`.
5. Следующий вопрос или итоговый черновик озвучивается через `TTS`.
6. При таймауте/прерывании (`barge-in`) управление остаётся в аудио-слое; в intent передаётся только подтверждённый текст.

### Минимальные требования к аудио-слою

- Короткие TTS-формулировки (1 мысль в вопросе), чтобы снизить когнитивную нагрузку в голосовом канале.
- Явная политика повторов: ограниченное число переспрашиваний и fallback на явный выбор `A/B`.
- Опциональная работа edge-first: сырой аудио-поток не обязателен для передачи в core, достаточно транскрипта.

## LLM-контракт (`LlmIntentClarification`)

При заданном `NEURAL_SERVICE_URL` используется LLM-реализация, иначе fallback на stub (`IntentClarification`).

### System prompt (ядро)

- Роль: `Product Factory Intent Clarifier`.
- Ответ: строго JSON, без markdown.
- Схема ответа:
  - `next_question: string | null`
  - `done: boolean`
- Правила:
  - один короткий вопрос формата A/B;
  - учитывать `goal`, `constraints`, `previous_answers`, `current_intent_draft`;
  - если уточнение завершено (или достигнут лимит 5 вопросов), вернуть `{"next_question":null,"done":true}`.

### Формат ответа

```json
{"next_question":"Что важнее: A) быстрый MVP или B) production baseline?","done":false}
```

или

```json
{"next_question":null,"done":true}
```

Оценка оптимальности протокола для сценариев «только текст» и «только аудио»: [intent-clarification-text-audio-optimality.md](intent-clarification-text-audio-optimality.md).
