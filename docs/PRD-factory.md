# PRD: Платформа Product Factory

**Версия:** 0.1  
**Статус:** черновик (фаза 1)  
**Дата:** 2026-02-19  

## 1. Цель и границы

**Цель:** платформа, которая по запросу создаёт **готовый deployable-артефакт** — репозиторий с кодом, тестами, IaC, документацией, CI/CD, наблюдаемостью и управляемыми AI-компонентами, соответствующий заданным стандартам.

**Границы MVP:**
- Один архетип продукта (API-сервис).
- Один контур: запрос → спецификация → репо → CI → staging.
- Агенты только как генераторы артефактов (спеки, планы, код); все side-effects через tool executor и политики.
- Solo-режим: один оператор, ручные approvals для high-risk.

**Вне границ MVP:** multi-tenancy, self-serve портал, прод-деплой без явного approval, несколько архетипов.

## 2. Пользователи и сценарии

- **Оператор фабрики (solo):** подаёт запрос на продукт, проверяет результат, принимает решение о promotion, настраивает политики и архетипы.
- **Потребитель (после MVP):** запрашивает новый сервис по «золотой тропе», получает репо и окружение без ручного копипаста.

**Основной сценарий:** оператор отправляет product request (цель + ограничения) → фабрика возвращает URL репо + статус деплоя в staging и отчёты (тесты, security, eval).

## 3. Критерии успеха

- **Cycle time:** «запрос → staging» в пределах целевого окна: 80% S-класс run (<30 мин), 95% M-класс (<2 ч). Классы и пороги — [decision-points-v1.md](decision-points-v1.md).
- **Automation Coverage:** доля шагов без участия человека ≥ baseline (см. [automated-development-model.md](automated-development-model.md)).
- **Quality Gates Pass Rate:** доля прогонов, прошедших CI + security + eval gates, без ручного обхода.
- **Воспроизводимость:** один и тот же запрос (при одинаковых политиках) даёт предсказуемый результат.

## 4. Ограничения и допущения

- Команда: 1 FTE (solo), часть работы выполняется агентами под контролем детерминированного контура.
- Стек: см. [ADR-0001](adr/0001-stack-and-prerequisites.md).
- Секреты и чувствительные данные не попадают в логи/трейсы; хранение — через выбранный механизм (Vault / env / облако).
- Регуляторика (AI Act, GDPR и т.д.) учитывается через risk register и gate-чеклисты; полноценный комплаенс — после фазы 6.

## 5. Зависимости и риски

- Зависимости: репозиторий, CI, среда staging, механизм секретов, хранилище логов/трейсов (см. ADR-0001).
- Ключевые риски: см. [risk-register.md](risk-register.md).
