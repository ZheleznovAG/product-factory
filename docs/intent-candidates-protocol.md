# Intent Candidates Protocol

Статус: draft (Phase A)

## Цель

После формирования `intent` (или пары `goal + constraints`) система должна предложить набор кандидатов результата для быстрого выбора пользователем.

## Вход

- `intent` (собранный из `intent.yaml`) **или**
- `goal + constraints` (если intent ещё не собран полностью)
- `runId` текущего запуска

## Выход

- Список из **3–7** кандидатов результата:
- Формат кандидата: краткое описание результата и/или ссылка на сгенерированный артефакт
- В рамках MVP допустимы текстовые описания (без генерации финальных артефактов)

## Протокол

1. Система нормализует вход (`intent` либо `goal + constraints`).
2. Генерирует 3–7 кандидатов результата (детерминированно или через LLM).
3. Показывает кандидатов пользователю как варианты выбора.
4. Пользователь выбирает один кандидат.
5. Выбор фиксируется в audit как `intent_candidate_selected`.

## Audit Event

Событие: `intent_candidate_selected`

Обязательные поля payload:

- `runId`: идентификатор запуска
- `candidateIndex`: индекс выбранного кандидата в выданном списке (0-based)

Опциональное поле:

- `reason`: комментарий пользователя, почему выбран этот кандидат (если предоставлен)

Рекомендуемое дополнительное поле:

- `candidate`: текст выбранного кандидата (для удобства анализа)

Пример payload:

```json
{
  "runId": "run-123",
  "candidateIndex": 2,
  "candidate": "Candidate 3: accelerated version focused on fastest time-to-first-value.",
  "reason": "Подходит по времени и уровню риска"
}
```

- Заглушка возвращает 3 детерминированных текстовых кандидата.
- При выборе ответа на шаге `select_intent_candidate` API пишет событие `intent_candidate_selected` в audit.
