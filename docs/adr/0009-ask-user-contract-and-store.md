# ADR-0009: Контракт ask_user и хранилище пользовательского ответа

**Дата:** 2026-02-26  
**Статус:** accepted

## Контекст

В roadmap и backlog Factory 2.0 предусмотрен human loop не только через бинарный approval/reject, но и через вопрос с вариантами ответа (`ask_user`). Нужен контракт данных и интерфейс хранения, чтобы workflow мог безопасно остановиться, дождаться выбора пользователя и продолжить run без прямых side-effects со стороны агента.

## Решение

1. Введён контракт `AskUserQuestion` со следующими ключевыми полями:
   - `runId`
   - `stepId`
   - `question`
   - `options` (список строк)
2. Введён интерфейс `AskUserStore`:
   - `saveQuestion(runId, question, options)`
   - `getPendingQuestion(runId)`
   - `submitAnswer(runId, choice)`
3. Для явной привязки вопроса к шагу workflow добавлена перегрузка:
   - `saveQuestion(runId, stepId, question, options)`
4. Добавлены реализации хранилища:
   - `InMemoryAskUserStore`
   - `FileAskUserStore` (один JSON-файл на `runId`, аналогично `FileApprovalStore`, директория по умолчанию `ask-user/`, переменная `ASK_USER_DIR`).

## Когда workflow может запрашивать ответ пользователя

- На любом шаге, где автоматическое продолжение создаёт неоднозначность по intent пользователя (например, выбор профиля, стратегии публикации, варианта генерации).
- На gate перед side-effect действием, если policy требует не approve/reject, а выбор из допустимых опций.
- Важно: `ask_user` не заменяет policy approvals для privileged действий, а дополняет их как механизм уточнения намерения.

## Как хранится и как продолжается run

- При постановке вопроса workflow сохраняет pending-запись в `AskUserStore`.
- Пока вопрос в статусе `PENDING`, run считается ожидающим пользовательский выбор на конкретном `stepId`.
- После `submitAnswer(runId, choice)` запись переходит в `ANSWERED`, фиксируется выбранный `choice`, и при следующем запуске/ретрае workflow читает ответ и продолжает сценарий из соответствующего шага.
- API-эндпоинты для `ask_user` в этом изменении не вводятся; добавлен только контракт и внутренний storage-интерфейс.

## Последствия

- **Плюсы:** появляется формализованный канал user choice для workflow без нарушения layer boundaries.
- **Минусы:** пока нет transport-слоя (HTTP/UI/CLI) для ввода ответа.
- **Смягчение:** интерфейс и file/in-memory store готовы для интеграции в API/оркестратор отдельным изменением.
