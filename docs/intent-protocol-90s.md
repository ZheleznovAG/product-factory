# Intent Protocol 90s (5 A/B вопросов)

Цель: за 60-90 секунд превратить сырой `goal + constraints` в черновик `intent.yaml` (Outcome / Experience / Constraints) для следующего шага планирования.

Протокол реализует Intent Layer и использует контракт [contracts/schemas/intent.schema.json](../contracts/schemas/intent.schema.json).

Уточнённый вариант с правилом "до первого результата задаём 3-5 вопросов" см. в [intent-clarification-protocol.md](intent-clarification-protocol.md).

## Когда применять

- На входе есть общий goal, но недостаточно ясно, какой именно результат и опыт нужны.
- Есть конфликтующие ограничения (скорость vs качество, бюджет vs охват).
- Нужен быстрый pre-intent перед запуском планировщика.

## Формат: 5 бинарных вопросов

Каждый вопрос имеет варианты `A` и `B`.
Если пользователь отвечает неопределенно, фиксируется `B` (более безопасный и консервативный вариант), и это явно пишется в `constraints.mustHave`.

1. **Результат:**  
`A` = "Сначала быстрый MVP/черновик"  
`B` = "Сразу production-ready baseline"
2. **Опыт взаимодействия:**  
`A` = "Максимум скорости, меньше проверок"  
`B` = "Больше проверок и объяснимости"
3. **Темп исполнения:**  
`A` = "Fast (итерации короткие, частые)"  
`B` = "Balanced/slow (меньше переключений, больше стабильности)"
4. **Жесткость ограничений:**  
`A` = "Разрешены компромиссы по неключевым ограничениям"  
`B` = "Ограничения must-have, без компромиссов"
5. **Критерий успеха:**  
`A` = "Главное — получить рабочий результат быстрее"  
`B` = "Главное — снизить риск регрессий и инцидентов"

## Примеры формулировок вопросов

- Q1: "Сейчас важнее быстрее получить работающий прототип (`A`) или сразу собрать устойчивый baseline для деплоя (`B`)?"
- Q2: "Предпочтителен режим 'быстро и проще' (`A`) или 'медленнее, но с валидациями и объяснениями' (`B`)?"
- Q3: "Идём короткими быстрыми циклами (`A`) или более размеренно с акцентом на стабильность (`B`)?"
- Q4: "Можно ослабить часть вторичных ограничений ради скорости (`A`) или держим все ограничения как строгие (`B`)?"
- Q5: "При равных условиях приоритет — time-to-value (`A`) или минимизация рисков качества/безопасности (`B`)?"

## Маппинг ответов в черновик Intent

- `outcome.goal`: исходный goal (нормализованный).
- `outcome.result`: вывод из Q1 + Q5 (например, MVP-first или production-baseline-first).
- `experience.feeling`: из Q2 (скорость vs уверенность/контроль).
- `experience.interactionStyle`: "5 A/B clarification protocol".
- `experience.tempo`: из Q3 (`fast`/`balanced`/`slow`).
- `constraints.mustHave`: исходные constraints + строгие выборы Q4/Q5.
- `constraints.mustNot`: формируется из явных запретов пользователя.
- `confidence`: начально 0.3-0.6 (draft), повышается после подтверждения человеком.

## Минимальный operational flow

1. Принять `goal + constraints`.
2. Задать 5 A/B вопросов (текстом, CLI или API).
3. Собрать ответы в `intent draft`.
4. Показать пользователю итоговый черновик для подтверждения.
5. Передать в planner только после подтверждения/accept.

## Примечания по реализации

- LLM для вопросов может быть заглушкой (template-based), без генерации side-effects.
- Хранить trace: вопросы, ответы, итоговый mapping в audit.
- В privileged контексте итоговый intent подтверждается approval-политикой перед изменяющими действиями.
