# Запрещённые действия агента

Список действий, которые агент **не имеет права** выполнять напрямую. Соответствует принципу из отчётов: «агент не продвигает изменения напрямую»; все side-effects — через tool executor, политики и при необходимости ручной approval.

## 1. Доступ и секреты
- **Запрещено:** читать или подставлять секреты из окружения/хранилища в промпты или в логируемый вывод.
- **Запрещено:** создавать или изменять учётные данные, ключи API, токены без вызова инструмента, разрешённого политикой и (для privileged) без human approval.

## 2. Инфраструктура и деплой
- **Запрещено:** инициировать деплой в production без явного разрешения (policy + при необходимости ручной approval).
- **Запрещено:** изменять desired state GitOps (репозиторий окружений) напрямую; только через разрешённый tool с записью в audit log.
- **Запрещено:** изменять сетевые правила, firewall, IAM/ACL вне перечня разрешённых инструментов и risk tier.

## 3. Данные и репозитории
- **Запрещено:** удалять репозитории или ветки без вызова инструмента с требуемым уровнем approval.
- **Запрещено:** массовое изменение или удаление данных в системах учёта (БД, object storage) вне контракта tool с idempotency и политикой.

## 4. Политики и конфигурация фабрики
- **Запрещено:** менять политики (allowlist, бюджеты, risk tier инструментов) без прохождения change-control и при необходимости human approval.
- **Запрещено:** добавлять новые инструменты с side-effects в реестр без прохождения Gate B и обновления threat model.

## 5. Поведение и потребление
- **Запрещено:** превышать заданные бюджеты (токены, число tool calls, wall-clock) без прерывания workflow политикой.
- **Запрещено:** выполнять неограниченные циклы вызовов (retry/повтор) без лимитов, заданных в контракте и политике.

---

**Как обеспечивается:** Policy Engine (OPA) как PEP перед каждым tool call; allowlist инструментов; risk tier и флаг `requires_human_approval` в контракте; sandbox executor с минимальными правами; аудит всех вызовов.

**Пересмотр:** при добавлении новых инструментов или изменении границ агентности — обновить этот список и threat model (фаза 6).
